# 「今天吃什么」菜谱模块（packageRecipe）

> 纯本地菜谱模块：**不依赖服务端、不接大模型、断网可用**。
> 独立子包 `packageRecipe`，40 道家常菜结构化数据 + 本地检索 + 冰箱模式 + 收藏。
> 数据/图片随小程序包分发，收藏存本机。图片许可说明见模块内「图片来源」页。

---

## 1. 设计目标

| 目标 | 做法 |
|---|---|
| 纯本地 | 数据、图片、搜索全部在小程序内，无网络请求、无登录 |
| 稳 | 无接口故障、无 AI 幻觉、可离线；搜索结果确定可复现 |
| 快 | 40 道数据在内存中检索，毫秒级；索引在启动时构建一次 |
| 小 | 子包约 0.73MB（19 张图 0.64MB + 数据/代码 0.09MB），远低于 2MB 限制 |
| 好看/协调 | 暖色系设计与主包一致；卡片、详情、冰箱模式统一视觉 |

## 2. 目录结构

```text
packageRecipe/

│  ├─ storage.js         收藏/历史/最近搜索（wx storage）
│  └─ view.js            页面展示辅助（封面/标签/版权）
```

## 3. 数据结构（每条菜谱）

```js
{
  id, title, aliases: [别名],
  category,            // 家常菜/快手菜/汤羹/主食/早餐/硬菜
  cuisine,             // 家常/川菜/粤菜/江浙/鲁菜/苏菜/台式/其他
  tags: [快手, 下饭, 清淡, 微辣...],
  time, difficulty, servings, heat,
  ingredients: [[名称, 用量], ...],
  steps: [步骤文本, ...],
  tips,
  image,               // /packageRecipe/assets/recipes/xxx.jpg（无图则空）
  credit               // 图片版权信息（页面展示/图片来源页）
}
```

领域约定：
- 食材名统一（番茄而不是西红柿；同义词在 `synonyms.js` 做查询扩展）
- 基础调料（盐/油/生抽/醋/葱姜蒜等）在冰箱模式视为“默认有”，不占选项
- 菜谱为通用家常做法，不涉及医疗/营养功效断言

## 4. 本地检索（不含大模型）

```text
用户输入
  → 归一化（全半角/空格/标点）
  → 查询解析：
      · 食材：从食材词典匹配（最长优先）
      · 时间：30分钟/半小时/1小时 等正则
      · 口味/标签/菜系：词典命中
      · 分词：词典最大匹配 + 中文 bigram 兜底
  → 多路召回：标题/别名/食材/标签/菜系/步骤文本
  → 规则排序：
      标题精确 +120 / 标题包含 +70 / 别名 +46
      + 食材命中 ×20
      + 标签/菜系 +8~16
      + token 命中 ×4
      + 时间符合 +14（不符合 -30）
      + 热度微加权
  → 模板化提示（“找到 N 道（食材：… · 30 分钟内）”）
```

特点：
- 完全确定性：同一查询结果稳定，可做回归测试
- 无结果时给出明确建议（只搜一个食材/放宽时间）
- 支持分类筛选、快捷标签（快手/清淡/下饭/汤/早餐/素菜）

### 冰箱模式

- 用户勾选现有食材 → 对每道菜计算：
  - 必需食材（排除基础调料）
  - 命中数 / 缺失数 / 覆盖率
- 排序：覆盖率降序 → 缺失少 → 耗时短
- 结果卡显示匹配进度条、还差哪些食材；全齐时提示“可以直接做”
- 无匹配时给出降级建议

## 5. 图片与许可

### 来源与策略

- 照片来自 **Wikipedia / Wikimedia Commons** 页面首图（按菜名批量查询）
- 许可白名单：Public Domain / CC0 / CC BY / CC BY-SA（避免 NC/ND/GFDL）
- 每张图记录：来源、许可、作者、原图页 URL；App 内「图片来源与许可」页可查
- 没有合格照片的菜谱 → **统一设计封面**（按分类配色的渐变 + 食物 emoji），
  不使用来源不明/不匹配的网图
- 禁止爬取下厨房、小红书等 UGC 图片

### 处理流程

```text
Wikipedia/Commons 取 1400px 缩略图
  → ffmpeg：scale 600:450 裁切 + 轻微饱和度/对比度统一
  → JPEG q6（约 25–50KB）
  → 放入 packageRecipe/assets/recipes/
  → credits.js 记录版权
```

当前：40 道中 **19 道有真实照片**，其余为设计封面；后续可按同一管线补图（换图只需替换 `assets/recipes/` 文件并更新 `credits.js`）。

## 6. 页面与交互

| 页面 | 功能 |
|---|---|
| 首页 | 搜索框、快捷标签、分类、今晚吃这个（换一个）、冰箱/收藏入口、推荐列表、最近搜索 |
| 详情 | 封面、分类/标签、时间/难度/份量、食材清单、步骤、小贴士、收藏、分享、相关推荐、图片来源 |
| 冰箱模式 | 食材多选、匹配度、缺料提示、结果点进详情 |
| 我的收藏 | 本地收藏 + 最近看过；空状态引导 |
| 图片来源 | 照片版权列表，点击复制来源信息 |

收藏/历史/最近搜索全部存 `wx.setStorage`，换设备不同步；无用户系统、无隐私上传。

## 8. 包体积与性能

- `packageRecipe` 约 **0.73MB**（19 图 0.64MB + 代码/数据 0.09MB）
- 单个分包限制 2MB、总包 20MB（以微信官方为准）；当前远低于限制
- 数据在页面初始化时一次性加载 40 条，检索在内存完成
- 列表图片 `lazy-load`；详情图 600×450，无需 CDN

扩容建议：
1. 40 → 120 道：图片总量约 3–4MB，需要拆成多个分类子包（每包 ≤2MB）
2. 或对非重点菜谱使用设计封面，仅重点菜谱保留照片
3. 纯本地模式下不要无限加图，先做体积预算（构建脚本可加 size check）

## 9. 构建与发布

```bash
# 1) 修改菜谱源数据（tools/recipe-build/build.py 的 RECIPES）
python tools/recipe-build/build.py          # 生成 data/recipes.js 等

# 2) 补图（可选，服务器执行；需 POINT_PASS 环境变量）
python tools/recipe-build/fetch_images_wiki.py

# 3) 本地静态检查
node --check packageRecipe/utils/*.js
cd D:/dsh/workplace/tools/wx-ci
node compile_check.js

# 4) 上传开发版
node upload.js --version 1.27.0 --desc "新增纯本地菜谱模块「今天吃什么」"
```

发布前检查：
- [ ] `app.json` 注册 `packageRecipe` 子包
- [ ] 首页入口可跳转
- [ ] 搜索/分类/冰箱/收藏/详情/图片来源可用
- [ ] 子包 ≤2MB、总包 ≤20MB
- [ ] 所有照片在 credits 中有来源/许可
- [ ] 无服务端请求（纯本地）
