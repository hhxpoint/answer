# 「我们的小火苗」发布与审核指南

> 本文说明：如何把当前代码上传为开发版、生成预览、设置体验版、提审与发布；
> 以及审核措辞、隐私协议、上线检查单。

---

## 1. 发布链路总览

```text
本地代码
  → 1) 静态检查（JS 语法 / WXML 处理函数 / app.json 页面注册 / 编译）
  → 2) miniprogram-ci upload（版本号 +1，robot=1）
  → 3) miniprogram-ci preview（生成预览二维码）
  → 4) 微信公众平台：开发版 → 设为体验版（手动）
  → 5) 添加体验成员（TA 的微信号）→ 真机验证
  → 6) 提交审核 → 审核通过 → 发布（均为手动）
```

> 小程序 AppID：`wx0c0dcd5aec680fb9`
> CI 上传密钥：本地保存（**不入库**，常见位置示例 `<本地路径>/private.wx0c0dcd5aec680fb9.key`）
> 上传密钥/AppSecret 的 IP 白名单：需包含当前执行上传的机器公网 IP；更换网络后要重新添加

## 2. CI 上传/预览命令（本仓库不含 CI 脚本，按以下方式使用）

在本地 CI 工具目录（示例结构）：

```text
tools/wx-ci/
├─ upload.js        # 上传开发版
├─ preview.js       # 生成预览二维码
├─ compile_check.js # 本地编译检查（不占用版本号）
└─ keys/            # 本地私钥（不入库）
```

```bash
# 编译检查（只本地校验，不上传）
node compile_check.js

# 上传开发版（版本号示例：1.27.0）
node upload.js --version 1.27.0 --desc "本次改动说明"

# 生成预览二维码（输出到 out/preview-*.jpg）
node preview.js --desc "预览说明"
```

说明：
- 开发版只能保留最新一个（每次上传覆盖 dev 版本）
- `robot` 固定为 1；上传成功会给出包体积（主包/分包/总包）
- 上传前的静态检查建议：
  - 所有页面 `.js` 可 `node --check`（ES module 文件报错属正常，以微信编译为准）
  - 页面处理函数存在（bind/catch 与 Page 方法对应）
  - `app.json` 的 `pages` / `subPackages` 与实际文件一致
  - `compile_check.js` 通过

## 3. 版本号与 tag

- 版本号规则：`主版本.次版本.修订号`，如 `1.26.0`
- 每次上传开发版递增修订号；功能批次可升次版本
- 建议在发布时打与版本号一致的 git tag：`v1.26.0`
- 变更必须同步到 [changelog.md](../../changelog.md)

---

## 4. 体验版（真机双人测试必需）

1. 上传完成后，公众平台 → 版本管理 → 开发版本 → **设为体验版**
2. 成员管理 → 添加 TA 的微信号为**体验成员**
3. TA 用微信打开体验版二维码（或从「最近使用」进入）
4. 双人流程测试：
   - 资料设置（头像/昵称）
   - 创建空间 → 分享/邀请码 → TA 加入
   - 小火苗互动、悄悄话、时光、纪念日、侧耳倾听
   - 邀请分享：非开发者打开分享卡片会进入线上版本，因此完整验证必须用体验版双方

> 注意：开发版/体验版不校验线上域名白名单之外的差异；但分享、订阅消息等仍受平台规则限制。

## 5. 审核措辞与功能描述

**模块命名**：`我们的小火苗`、`悄悄话`、`我们的时光`、`我们的纪念日`、`侧耳倾听`

**建议描述**（避免敏感词）：

> 双人私密空间：仅绑定双方可见，用于记录两个人的日常、纪念日与语音留言；
> 无公开内容、无陌生人互动、无实时语音通话。

**避免使用**：社交、交友、陌生人聊天、情侣匹配、语音聊天室、直播等词。

**功能说明需体现**：
- 需要先绑定（邀请码/分享）才能使用
- 内容仅双方可见，支持撤回/删除
- 已接入内容安全（文本 + 语音）
- 举报/违规处置路径（管理员后台可审计/下架）

## 6. 隐私保护指引（发布前必做）

公众平台 → 设置 → 基本设置 → **用户隐私保护指引**，按实际使用声明：

| 权限/信息 | 用途说明示例 |
|---|---|
| 麦克风（录音） | 用于录制双人语音留言，并用于内容安全检测 |
| 相册/摄像头（图片） | 用于发布时光相册照片 |
| 位置（如保留天气/运动） | 用于天气服务与运动记录 |
| 用户信息（昵称/头像） | 用于双人空间展示身份 |

> 若隐私指引与实际调用 API 不一致，审核会被驳回或线上被限制。

## 7. 上线检查单

### 小程序端
- [ ] 静态检查 + `compile_check.js` 通过
- [ ] `app.json` 页面注册完整，无缺失页面
- [ ] 小火苗模块：资料 → 绑定 → 首页 → 各子模块全流程
- [ ] 分包体积与总包体积在限制内
- [ ] 分享标题/封面正确，邀请路径正确
- [ ] 异常态：无网络、拒绝权限、服务端错误均有提示

### 服务端
- [ ] `couple.service` active，`/couple-api/health` 200
- [ ] 数据库有备份，磁盘/内存有余量
- [ ] 内容安全：消息推送配置有效，回调 200（日志可见）
- [ ] OJ 后台 `/admin/couple/` 可正常登录查看
- [ ] 上传/播放/撤回/审核状态端到端验证

### 平台配置
- [ ] 服务器域名（request/socket/download）包含 `https://hhxpoint.me`
- [ ] 消息推送 URL/Token/AESKey 与服务器 `.env` 一致
- [ ] 隐私保护指引已更新
- [ ] 版本描述与实际改动一致

---

## 8. 回滚

- 小程序：公众平台可回退到线上历史版本（版本管理 → 线上版本 → 回退）
- 服务端：保留上一版代码/数据库备份；按 [../ops/runbook.md](../ops/runbook.md) 恢复
- 后台：`deploy_oj_admin.py` 失败会自动回滚 `app.py` / `base.html` 并重启 OJ
