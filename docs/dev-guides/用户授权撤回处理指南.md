# 用户授权撤回邮件处理指南

## 背景

2026-03-25 首次收到微信团队发送的「用户撤回授权信息」通知邮件，附件为 `attachment_20260324.csv`。

## 为什么纯前端小程序也会收到此邮件

只要小程序申请过任何用户权限，且有用户撤回了授权，微信就会自动发邮件通知开发者。**跟你是否存储了用户数据无关。**

## 本项目申请的权限清单

| 权限 | 来源 | 使用页面 |
|---|---|---|
| `scope.userLocation` | `app.json` requiredPrivateInfos | packageSport（运动定位）、packageWeather（天气） |
| `scope.record` | 页面内主动请求 | pages/emotion-analysis（语音录音） |
| 相册/媒体选择 | `wx.chooseImage` / `wx.chooseMedia` | packagepdf/img2pdf、pages/process、packageGithub/translate |

## 邮件附件字段说明

| 字段 | 含义 |
|---|---|
| CreateTime | 撤回时间的时间戳 |
| OpenID | 用户唯一标识 |
| AppID | 小程序 AppID |
| RevokeInfo | 撤回的授权类型（14 = 选中的图片或视频） |
| OpenPID | 公众号 OpenID（如有） |
| UnionID | 跨应用统一标识（如有） |

## RevokeInfo 常见值

| 值 | 含义 |
|---|---|
| 1 | 用户信息（昵称、头像等） |
| 2 | 手机号 |
| 3 | 地址 |
| 14 | 选中的图片或视频 |

## 本项目为何无需处理

**三个原因：**

1. **不以 OpenID 为 key 存储数据** — 所有本地存储 key 是固定字符串（`userProfile`、`learningCenterData`、`emotionHistory` 等），跟微信身份无关，无法按 OpenID 定位到某个用户的数据。
2. **图片/视频都是临时文件** — `wx.chooseImage`/`wx.chooseMedia` 返回的 `tempFilePath` 是小程序临时目录下的文件，不持久化，系统会自动清理。
3. **没有后端服务** — 不存在服务端存储用户隐私数据的情况。

## 未来接入后端时的处理方案

如果以后用 `wx.login` 获取 openid 并关联用户数据，需要：

1. **配置消息推送**（官方推荐方案）：在微信公众平台配置消息推送地址，接收 `user_authorization_revoke` 事件，实时删除用户数据。
2. **或手动处理邮件附件**：每日下载 CSV，解析 OpenID，从后端删除对应用户数据。
3. **在 `app.js` onLaunch 中加入清理逻辑**：用户再次打开小程序时，检查本地是否有需要清理的数据并执行删除。

```javascript
// 未来需要时的示例代码
App({
  onLaunch() {
    const revokedOpenId = 'xxx'; // 从后端或配置获取
    const profile = wx.getStorageSync('userProfile');
    if (profile && profile.openid === revokedOpenId) {
      wx.removeStorageSync('userProfile');
      // 清理其他相关数据...
    }
  }
})
```
