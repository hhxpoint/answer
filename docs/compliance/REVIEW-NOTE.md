# 审核说明 · 个人主体「社交-笔记」类目被拒

> 背景：2026-11-26 审核反馈「存在个人主体小程序未开放的服务类目……用户自行生成内容（文字、图片、音）的记录、分享，属社交-笔记范畴」。
> 本文档说明我们已经做了什么、提交时该怎么写、以及仍被拒时的备选方案。

---

## 1. 这个模块到底是什么

「小火苗」是**两个人之间的私密互动工具**，不是社交平台：

| 有 | 没有 |
|---|---|
| 两人绑定后的共同空间（最多 2 人） | 广场 / 推荐 / 热门 / 社区 |
| 两人之间的日记、语音、纪念日、小游戏 | 关注 / 粉丝 / 评论 / 点赞 |
| 邀请码邀请对方加入（一对一） | 公开发布、公开主页、内容转发 |
| 内容仅双方可见 | 陌生人搜索、按标签发现 |

**关键事实：分享卡片不携带任何用户内容。** 全模块 14 个页面的分享回调都指向通用首页/邀请页，标题为固定文案，没有把日记、语音、图片放进分享卡片。

---

## 2. 这一版做了什么（提高通过率）

1. **使用边界说明**：在 8 个关键页面底部加了统一小字——
   - 「仅限两人私密互动工具 · 内容仅你们双方可见」
   - 「不提供公开发布 / 广场 / 推荐 / 关注 / 评论 / 内容转发」
   覆盖：加入关系空间（bind）、邀请加入（join）、创建空间（create）、空间列表（spaces）、小火苗首页（home）、聊天（chat）、时光线（timeline）、语音（listen）。
2. **文案与功能对齐**：核对全模块无「广场 / 推荐 / 关注 / 评论 / 公开 / 热门 / 社区」字样，说明不是套话。
3. **分享面收敛**：分享只用于「邀请对方绑定」和「打开小程序」，不传播用户内容。

## 3. 提交审核时填的备注（可直接复制）

```
【功能说明】
本小程序为两人之间的私密互动工具（生活服务类），用户需通过对方发送的邀请码
一对一绑定，每个关系空间最多 2 人。绑定后可在两人之间记录日记、语音、纪念日，
一起养一只虚拟小火苗。所有内容仅绑定双方可见，不对外展示。

【不存在社交能力】
小程序内不提供公开发布、广场、推荐、关注、粉丝、评论、点赞、话题、社区、
内容转发等任何社交功能；未接入任何内容推荐或陌生人发现机制。
分享能力仅用于「邀请对方绑定」与「打开小程序」，分享卡片不携带任何用户内容。

【内容管理】
用户内容仅在双方之间可见；解除关系后该空间内容对双方不可再访问。
如涉及违规内容，可通过「我的-反馈」联系开发者删除，我们承诺 24 小时内处理。

【类目说明】
小程序主体为个人，功能定位为私密工具而非社交平台，恳请按「工具-生活服务」
类目审核。
```

> 如果后台有「审核备注 / 补充说明」输入框，就把上面整段贴进去；没有的话，在「版本描述」里精简成前两段。

| 位置 | 建议文案 |
|---|---|
| 小程序简介 | 「两个人之间的私密互动小工具：一起记录日常、留语音、纪念日，养一只属于你们的小火苗。内容仅双方可见。」 |

| 用户隐私保护指引 | 明确：收集头像昵称用于展示；日记/语音仅存储于双方空间；不向第三方共享 |

## 5. 如果还是被拒

按可能性排序：

1. **主体类型是硬门槛**：个人主体确实不能开「社交-笔记」类目。若审核员仍按类目判定，唯一彻底解法是**企业主体**（个体户营业执照也可），或把小程序迁到已有企业主体下。
2. **移除 UGC**：去掉日记/语音（保留纪念日、小游戏、提醒），改成纯工具，可继续用个人主体——但这会砍掉产品核心，不建议。
3. **拆分**：主小程序只保留工具功能（纪念日/提醒/小游戏），UGC 部分另做企业主体小程序。

我建议先按第 3 节的备注重新提交一次；如果仍被拒且理由是「类目」，那就是主体问题，需要你决定是否走企业主体。
